# Measure Lab 0.11 — трассы и размеры настоящего пола

## Область

`web/lab-floor-routes.js` работает в виде плана помещения (`S.room.ms`), а не на схематичной глубине пола в локальном 3D-виде стены. Исходная v81 неизменна. `scripts/floor-routes-patch.py` с точной проверкой единственного вхождения отключает повторное штатное рисование трасс плана. Общий модуль сохраняет различие пола и потолка (`lvl:'f' / 'c'`); остальная геометрия остаётся штатной. Старый потолочный рисунок [3,4] сохраняется для трасс без явно заданного стиля.

Нужен план минимум из двух точек: незамкнутый участок поддерживается. Пустое помещение без стен не принимает новые трассы и размеры, поскольку такой объект не может пройти штатный экспорт. Предлагается сначала создать план.

## Взаимодействие

- «Трасса пола» включает штатный инструмент `PL.tool='prt'`. Один жест создаёт трассу из двух точек на реальном плане. Кнопка пола явно выбирает `lvl:'f'`, а общий инструмент трассы уважает выбор «пол / потолок» в штатной панели. Пользователь может последовательно провести сегменты тёплого пола и других коммуникаций.
- Параметры берутся из `zo('prt')`: тип, L, P, пунктир и привязка. Сначала применяется направление P, затем L; при обоих модификаторах конечный результат ограничен осью. Привязка не нарушает заданное направление.
- Выбранная трасса имеет ручки вершин. Ручка редактируется тем же инструментом без создания новой трассы; в «выборе» можно тянуть трассу целиком. Старые сохранённые многоточечные трассы сохраняют все вершины.
- Десять типов, цвета, коды и рисунки штриховки берутся из общего каталога. Выбор не подменяет цвет типа синим: синие только ручки. Один компактный код размещается у самого длинного сегмента при достаточном месте.
- «Размер пола» создаёт размерную линию между произвольными точками плана, не только между вершинами стен. Наконечники и поле рисуются без поперечных засечек. После создания клавиатура не открывается.
- Касание поля открывает штатные `#w3f` и клавиатуру приложения. Введённое значение хранится отдельно в миллиметрах. До ручного ввода расчётное значение помечено «≈»: используется масштаб существующих измеренных стен, не выдаётся за новый точный замер. Изменение конца снимает старое ручное значение; перенос линии целиком его сохраняет.
- Поворот поля следует линии; после открытия проверяется фактический DOM-прямоугольник поля относительно клавиатуры и холста, при необходимости сдвигается только вид.
- Нативная политика стилуса сохранена: после стилуса палец перемещает вид, а не рисует. Ладонь во время работы пера игнорируется. Преднамеренное касание поля доступно; протяжка по полю сдвигает вид.
- Создание и редактирование используют атомарные предварительные копии. Данные и история меняются одним штатным `plSnap` только при успешном отпускании. Отмена указателя, щипок, смена комнаты/инструмента/типа отбрасывают предварительную копию без изменения undo/redo.

## Хранение и обмен

- Трассы: штатные `ms.rt[{id,t,lvl:'f'|'c',pts,d,...}]`; дополнительные `dash` и ограничения направления не теряются.
- Произвольные размеры: дополнительное `ms.labFloorDims[{id,a,b,v?,units?:'mm',...}]` внутри реального помещения. Штатная история холста включает весь `ms`, поэтому отмена и сохранение работают без отдельного параллельного хранилища.
- Тип и опции трасс пола сохраняются в отдельном ключе `measure.lab.routes.floor.options`, поскольку старый конструктор `PREF` не загружает все дополнительные опции.
- `zpOut` повторно использует нативный экспорт и дополняет метаданные. Y переводится в направление листа, а при восстановлении возвращается обратно; длины и названия не выдумываются.
- Нативный `zImpExp` восстанавливает маршруты; обёртка восстанавливает дополнительное `labFloorDims` у созданных помещений. Это требуется, потому что штатный импорт перечисляет поля `ms` явно.
- `zwSet` конструктора сохраняет весь объект `ms` клонированием, поэтому новые размеры и стили можно проверить в его состоянии. Полный конструктор пока не содержит согласованного визуального представления произвольных размеров пола; наличие метаданных в JSON не выдаётся за подтверждение их отображения или редактирования в конструкторе. Новые типы трасс также требуют отдельной проверки визуальной классификации на стороне конструктора.

## API для интерфейса и QA

`MeasureLabFloorRoutes`: `selected`, `selectedDimension`, `setType`, `defaultType`, `setRouteTool`, `setDimensionTool`, `handles`, `dimensionLabels`, `hit`, `value`, `scaleInfo`, `paint`, `openDimensionField`. Тесты создают объекты настоящими жестами, а не вызовом функций создания.
